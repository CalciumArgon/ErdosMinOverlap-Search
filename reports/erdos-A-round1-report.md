## 2. evaluator / 搜索策略改进思路(本轮已实现)

**评估层**:程序返回 `(breaks, values)`(Fraction 断点+段值,m≤64、分母≤2²⁰),evaluator 解析配平末段值后,用**折点引理**精确枚举:M(s)=Σ v_p(1−v_q)·λ(I_p∩(I_q−s)) 分段线性、折点恰为断点两两差,sup 必在折点取 → 扫描线 O(m² log m²) Fraction 精确求 max,向上舍入得**严格上界 U**。分数 = 1/(1e-8+U),证书上下界零间隙。legacy 3 元组走原 float 管线(逐位一致),供热启动。

**信号层**:evaluator 免费产出并存入 node.metrics(自动进 inspiration 提示词):`active_shifts`(达到 max 的平移,精确分数)、`active_sensitivity`(折点两侧精确斜率 + 沿配平流形的值/断点导数)、`equioscillation_count`(等振荡数,凸半无限规划 KKT 视角下的"离最优多远"指标)、`n_segments/n_kinks`、证书区间。

**框架层**:宽容抽取回退(缺 EVOLVE-BLOCK 标记时取最后一个 python 块)、rpucg 提示词规则 5(只回代码块)、scheduler 在飞计数补丁。

## 4. 结果分析

### 4.1 机制层:完全达标
宽容抽取把拒收率从 100% 压到 0;精确内核全程零噪声打分,证书上下界零间隙;诊断字段 37/38 个 A类节点完整;非法候选带精确错误码进入失败模式通道。**评估基建没有发现任何缺陷**。

### 4.2 搜索层:结构种子断裂(最大问题)
40 个候选里 14 个是平凡 h≡1/2,链 2 从 2.46 爬起、链 0 从 2.0 爬起。根因:**热启动是 legacy 2400 维浮点程序,而 A类档案/提示词里没有任何 A类结构种子**——模型看到的 inspiration 是 2400 行网格程序,无法翻译成断点+段值,于是每条链都从零重新发明结构。链 2 的爬升(2.46→2.5958→2.5968)证明**只要起点有结构,rpucg 的精化是有效的**;但三批演化(L=3)从 h≡1/2 起步远不够逼近 0.3809。

### 4.3 信号利用:敏感性没被用起来
诊断字符串(如 `v0:+0.2500 b1-:-0.3784`)显示大量候选存在明确的一阶改进方向,但模型更倾向自己写优化器(平均 281s 的评测耗时说明模型在构造里内嵌了长时间搜索循环),而不是顺着敏感性的方向做结构编辑。等振荡数全部 ≤2(最优解应有多 shift 同时卡脖子),说明模型从未进入"平衡阶段"。

### 4.4 成功案例
- chain 2 gen 9(2.5968):8 段结构、c5=0.385083、证书 [0.3850825, 0.3850825]、active shifts {1/4, −1/2, 3/4}——干净的小段数结构,接近但未超越论文解;
- chain 0 gen 4(2.5768):8 段、41 折点、equiosc=2——出现了两个几乎并行的 active shift,方向正确。

### 4.5 失败案例
- 14 个 h≡1/2 候选:模型保守输出,浪费 35% 预算;
- 3 个非法候选:协议细节错误(返回格式、端点),错误码可教,下一批即可自纠;
- 大分母漂移:active shift 出现 349460/1015837 这类结构,增大后续变异解释成本。

### 4.6 主要瓶颈排序
1. **A类结构种子缺失**(热启动与表示脱节)——影响面最大;
2. **诊断信号不可执行**(原始导数 vs 可执行动作)——模型不跟随;
3. **35% 预算浪费在平凡候选**(h≡1/2)——需要更强提示或惩罚;
4. 预算浅(L=3 步/链)与评测墙钟高(候选内嵌优化器)——次级。

## 5. 本轮改进方案(第二轮前实施)

### 5.1 init 热启动 legacy→A类压缩(init_program.py)
理由:解决瓶颈 1。把论文 2400 维向量**压缩为分段 spec**:值量化到 1/16(不满足 m≤64 时逐级粗化到 1/8、1/4、1/2、最终 0/1 阈值),合并相邻同值段,断点取网格位置(分母 1200 ≤ 2²⁰)。init 节点成为 A类节点(其 U 分即压缩结构的分),链共享构造从 spec 开始,模型看到的每个 inspiration 都是可读的结构化断点表。风险:压缩分可能略低于 2.6256(预计 2.61 附近),但换来的是结构种子。

### 5.2 可执行诊断(evaluator.py)
理由:解决瓶颈 2。在 build_diagnostics 增加:
- `snap_hints`:对 top-3 active shift,用 `Fraction.limit_denominator(64)` 给出最近小分母有理近似与精确重算的分数差(`s=349460/1015837 ≈ 11/32, snap ΔU=+2.1e-6`)——直接给出"把结构对准哪个有理数"。
- `local_optimal`:全部一阶敏感性 |d| ≤ 1e-9 时置 true("当前结构在自由参数方向已局部最优,需要结构变化:分裂/合并段")——给模型阶段信号。
- `move_hints`:对最佳 shift 给出 top-1 精确动作(哪个参数、哪个方向、每单位移动的精确收益)。
全部零引擎改动、零新增依赖、纯 Fraction 计算。

### 5.3 不改的部分
- 内核、路由、证书、legacy float 路径、错误码协议均不动(第一轮证明其正确性);
- 引擎/提示词不动(保持与第一轮可比性)。
