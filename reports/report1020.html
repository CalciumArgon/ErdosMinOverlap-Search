LAST TWO WEEKS

版本 1 · exact rational evaluator

第一周加入 A 类精确有理 evaluator：候选输出断点和值，内核用 Fraction 扫描所有可能的 kink，并给出严格的 score certificate。论文的 2400 格浮点解仍作为 warm start，但它和 A 类表示并不匹配。

结果是 evaluator、证书和错误码都稳定工作，41 个节点中 38 个有效，最好仍是论文 warm start：c5 ≈ 0.3808677。14 个候选退化成 h ≡ 1/2，说明主要瓶颈不是算分，而是模型没有继承到正确的结构。

版本 2 · compressed warm start

第二周把论文解压成约 300 段的 A 类结构，修正 tail split、质量平衡和端点，并加入 local_optimal、move_hints、snap_hints。模型现在看到的是“可以直接编辑的结构”，不再是 2400 行浮点程序。

表示问题和评测耗时明显改善：平均评测从 280.8 秒降到 14.3 秒，最佳演化候选距离 init 只有约 0.15%。但 26/40 个候选又回到了常数解，且高质量候选撞到 512 段上限；可见结构化输入解决了“看不懂起点”，没有解决“不会利用搜索信号”。

连续函数+分数松弛 error bound

PROOF NOTE
|C₅(f) − C₅(g)| ≤ 2 ||f − g||₁

目标函数对 L¹ 距离稳定。只要能两个函数的距离小，目标值的差就有直接上界。

第一层：连续函数 → 均匀网格

  • 若 h 一致连续：误差 ≤ 4ωh(1/N)。
  • 若 h 是 Lipschitz，常数为 L：误差 ≤ 2L/N。
  • 前提是候选确实来自这个固定连续函数的格心采样。

第二层：分数网格 → 二值网格

  • 必须指定二值化规则 QN。
  • 必须实际证明 ||hN,rel − hN,bin||₁ ≤ εN。
  • 二值化造成的目标变化 ≤ 2εN。

条件性总界：

|C₅(hrel) − C₅(hN,bin)| ≤ 2L/N + 2εN

这个公式需要已知的正则性、明确的二值化规则和实际的 εN。它不是当前任意搜索数组的自动误差证书。

Current

THIS WEEK / MOTIVATION

新的假设：一个低分（好的解）到底是在告诉我们“找到了更好的对象”，还是只是在告诉我们“只是这个 relaxation 上更容易优化而非真实解更好”？（与gt的误差变大了）

从前两轮看到的根本矛盾

前两轮不断改善 evaluator、warm start 和诊断，但真实目标没有改善。模型会把好解改坏，也会返回容易写的常数模板；更重要的是，A 类 exact evaluator 把连续网格和二值集合之间的 gap 暂时藏起来了。我们可能一直在优化一个更方便计算、但不等于原问题的目标。

所以版本 3 不再给模型大量“好解应该是什么形状”的提示，而是把判断权交给模型：让它检查网格分辨率、分数值取值和搜索过程本身会不会制造假象。

本轮想验证的直觉

  1. 如果模型知道分数只是 relaxation，它会少交白卷，也会更谨慎地解释结果。
  2. 如果低分来自网格 artifact，加密网格后应该明显变差。
  3. 如果低分主要来自 fractional smoothing，二值化后应该出现可测的 gap。
  4. 如果 warm start 本身已经很好，模型应先保护基线，再做小扰动，而不是每次重写一个粗糙优化器。

改动

本轮补齐了 Qwen gateway 的 thinking_budget 透传，并把 reflection 固定成短格式，解决了上一版深度思考导致的空输出和超时问题。代码提取、独立重算和共享 warm start 都继续沿用，工程目标是让本轮变化主要发生在“模型如何解释证据”，而不是发生在 evaluator 数值逻辑里。

进步

模型不再只看 score 大小。它主动做二值化实验，知道需要区分网格 artifact 和 fractional artifact，也开始质疑“我拿到的分数是不是我以为的那个函数”。

仍未解决

模型没有超过 warm start。很多候选仍用粗糙的 subgradient、模拟退火或内嵌长循环，先把已有好解破坏，再用有限预算试图修复。

证据的边界

“二值化后变差 4.6%”只说明这个候选存在明显 relaxation gap。它不能直接代表原始 binary optimum 与 relaxed optimum 的精确差距。

可能不是继续迭代就会变好

RESET THE QUESTION

如果只沿着版本 1 → 2 → 3 的路线继续加诊断、加段数、加 thinking budget，可能会得到更长的搜索，却不一定得到更可靠的科学结论。现在至少有三个更根本的风险。

01

我们优化的对象可能一开始就不是原始问题

legacy-grid 的低分同时享受了有限网格和分数值两层自由。A 类 exact evaluator 解决了“如何精确评估返回函数”，却没有解决“返回函数离二值集合有多远”。如果不把二值化和 grid refinement 变成每个候选的标准测量，搜索 score 越高，解释风险可能越大。

02

LLM 可能不适合直接承担非光滑数值优化

模型可以提出结构和实验，但当前结果显示它会把一个很好的 warm start 交给一个不稳定的内嵌优化器。C5 是多个 shift 的最大值，局部方向会在 active shift 切换时改变；让语言模型自己写长时间数值优化循环，既浪费评测预算，也很难保证不破坏 incumbent。

03

“搜索更多”不是“证据更多”

三轮都没有超过论文解，这个事实本身不能说明论文解接近全局最优，也不能说明框架搜索能力不足。我们需要拆开两个问题：一是给定候选的可靠性和 relaxation gap；二是算法是否能在同一表示下稳定改善一个已知好解。

本周结论

版本 3 的还没产出更低（好）的 c5，但发现了可测的“分数值到二值”的差距，并证明模型可以产生一些可靠性验证（加密格点验证等）。下一轮的第一目标应从“让模型继续搜”改成“让每个候选都留下可比较、可复核的证据”。

计划

NEXT EXPERIMENTS

把二值化后的解变化量放进evaluator中一起考虑

① 对同一个候选跑多个网格分辨率，记录 N 变化后的 c5。

②执行二值化（模拟退火只是一种，可能存在更好的 0/1 化路线）并记录二值化后的 c5 和变化量

最后把所有候选结果的 score / refinement / binaraization 一起记录并评估。让生成器考虑这样一个目标“生成的解在不同松弛下保持稳定，避免是一个仅仅在好优化的空间中好的解，而非真实空间好的解”

少让LLM直接做优化器的改动

结果有这样的趋势：LLM 会在 warm start 的解的基础上对优化器胡乱改动，那么只让 LLM 对优化器做小扰动和结构假设，确定性代码负责 line search、质量保持和 incumbent 保护。
