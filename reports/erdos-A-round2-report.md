## 3. 分析

### 3.1 改进生效的部分(本轮目标达成度)
1. **结构种子 ✓**:init 从"2400 维浮点程序"变为 300 段可读结构,链的首批候选全部从该结构出发(chain 0 首批 2.605/2.401/2.621;chain 1 首批 2.605/2.611);
2. **评测成本 ✓**:模型不再内嵌长时优化器(有种子+方向提示后改为结构编辑),墙钟 2.4h→1.6h;
3. **信号质量 ✓**:active shifts 全部小分母,snap_hints/local_optimal/move_hint 全部落盘;
4. **演化接近度 ↑**:最佳演化候选离 init 差 0.15%(第一轮差 1.1%)。

### 3.2 仍然失败的部分
1. **依旧无人越过热启动**(两轮 × 40 候选);chain best 全部停留在 init;
2. **平凡候选恶化(35%→65%)**:26/40 返回 h≡1/2。根因假设:`_default_spec()`(h≡1/2,8 块)随 init 程序全文嵌入每条 prompt,模型大量"改进"这个合法且易写的模板;它永远拿 2.0 分但从不被罚;
3. **等振荡数停留 1-2**:候选从未进入平衡阶段(论文解应有多个 shift 同时卡脖子);
4. **512 段封顶**:精化候选撞上限,说明结构细化还有空间,但段数上限也是内核成本上限。

### 3.3 成功/失败案例
- 成功:chain 0 gen 0 的 2.621232(m=512、974 折点、active ±37/64 等)——对 300 段种子做了大量局部精化,损失 0.15%;
- 失败典型:26 个 h≡1/2(含把种子"简化"成均匀分布的情况);2 个 RuntimeError(模型写错 numpy 索引)。

## 4. 结论与下一步方向猜想(多种,不锁定)

| # | 方向 | 依据 | 预期 |
|---|---|---|---|
| A | **移除 h≡1/2 默认陷阱**:init 的 `_default_spec` 换成非平凡结构;instruction 明示"uniform h≡1/2 scores 2.0,不要返回它";evaluator 对全同值 spec 加 `degenerate=True` 诊断 | 65% 预算浪费的直接根因 | 预算利用率翻倍以上 |
| B | **evaluator 自举一步改进**:evaluator 沿 move_hint 做精确线搜索,把"应用该动作后的新 spec + 新分数"作为诊断返回(教模型"照这样做就涨分") | 模型不跟随导数;用具体例子教 | 敏感性真正被利用 |
| C | KKT witness:active set 上验证质量梯度锥包含性(局部最优性证书) | 当前 local_optimal 是阈值启发式 | 更准确的阶段信号 |
| D | 段数上限 512→1024(内核实测 512 段秒级,1024 可承受) | 候选撞上限 | 更细的结构 |
| E | 预算加深:max-generations 80、L 5-6 步/链 | 演化 3 步就到预算 | 链内精化更长 |
| F | xhigh 对照实验(单次 ~18min,成本 2×) | 思考深度是否瓶颈未验证 | 候选质量可能跃升 |
| G | 提示词层:rpucg 加"当前最优结构诊断"专段(引擎改动) | 诊断信息密度仍低 | 注意力提升 |
| H | 显式 crossover:断点并集/块值交叉(框架改动) | 结构空间天然可组合 | 继承好块 |
| I | B类分段线性(四次多项式+区间 enclosure) | 中间值结构的原生表达 | 表示能力升级 |

**推荐下一轮组合**:A(除陷阱)+ B(自举示例)+ D(放宽上限),保持其余配置不变,做 A/B 对照。
